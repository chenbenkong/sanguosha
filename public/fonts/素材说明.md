# 字体素材说明

本目录的三份 woff2 是**按游戏实际用字裁剪**的子集，不是完整字体。随附 `OFL.txt` 为原始许可。

## 文件

| 文件 | 体积 | 用途 | 上游 |
| --- | --- | --- | --- |
| `MaShanZheng-sub.woff2` | 596 KB | 标题书法字（`.font-ancient`）| [Ma Shan Zheng](https://github.com/googlefonts/mashanzheng)，OFL |
| `NotoSerifSC-400-sub.woff2` | 283 KB | 正文衬线（常规）| Noto Serif SC，OFL |
| `NotoSerifSC-700-sub.woff2` | 292 KB | 正文衬线（粗）| 同上（variable 轴实例化到 wght=700）|
| `OFL.txt` | 4 KB | 许可原文 | Ma Shan Zheng |

## 为什么要有这一层（历史问题）

这三个文件**此前从未被任何 `@font-face` 引用过** —— `index.html` 里 preload 了，
CSS 里却一条 `@font-face` 都没有，等于装饰品。后果是：设备没装「Ma Shan Zheng」时
（Android WebView 基本没装），标题字**静默回退**成系统字形。

更糟的是当时那三份子集**只有拉丁字形**：实测所有汉字的渲染宽度都等于回退字体
（「三国」= 120px = 3×40 全角），只有 `A`/`a`/`1` 等拉丁字符宽度不同。
也就是说离线单机时标题的书法字实际是错的。

## 现在的处理

1. 取上游完整版（Ma Shan Zheng 5.8 MB / Noto Serif SC variable 24 MB）
2. 扫描 `src/**` 与 `App.tsx`/`constants.ts` 里出现的全部汉字 + 标点 + 拉丁，
   得到 1460 个码点（其中 CJK 1359 个）
3. 用 fontTools 裁子集并压成 woff2：`MaShanZheng` 5.8 MB → 596 KB；
   Noto Serif SC 先 `varLib.instancer` 实例化到 wght=400/700 再裁，各约 285 KB
4. `theme.css` 里补 `@font-face`，`font-family` 仍写 `Ma Shan Zheng` ——
   所以**装了系统字体的设备照旧优先用系统版本**，没装的自动落到内置子集

## 复现命令

```bash
python -m pip install fonttools brotli

# 1) 取完整版（OFL 开源）
curl -LO https://raw.githubusercontent.com/google/fonts/main/ofl/mashanzheng/MaShanZheng-Regular.ttf

# 2) 裁子集（glyphs.txt 是扫描源码得到的字符集，每行一个字符）
python -m fontTools.subset MaShanZheng-Regular.ttf \
  --text-file=glyphs.txt --flavor=woff2 \
  --output-file=MaShanZheng-sub.woff2 \
  --layout-features="*" --no-hinting --name-IDs=1,2,3,4,5,6
```

校验（子集里必须真的含 CJK 码点，不能只有拉丁）：

```bash
python -c "from fontTools.ttLib import TTFont; \
g=TTFont('MaShanZheng-sub.woff2'); cm=g.getBestCmap(); \
print('CJK 码点:', len([k for k in cm if 0x4e00<=k<=0x9fff]))"
# 期望 1359（若接近 0，说明子集只含拉丁，中文会回退）
```

## 注意

- 字体 URL 在 CSS 里必须写**相对路径**（`../../fonts/xxx.woff2`）。
  绝对路径 `/fonts/…` 在 APK 的 `file://` 下会解析成 `file:///fonts/…` 而失效。
- 新增大量汉字（例如新武将名）后要**重新扫描并裁一次**，否则新字会回退。
  受 `src/components/builtinFont.test.ts` 的体积守卫保护（小于 100 KB 视为只含拉丁）。
